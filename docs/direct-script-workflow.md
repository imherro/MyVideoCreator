# 直接剧本创作入口

## 使用路径

- 新建作品默认选择「直接写剧本」，创建后进入 EP01 剧本室。选择「从原著改编」则进入原著资料库。
- 剧本室直接编写、粘贴、保存正文，无需原著、事件提取或分集规划。保存后可进入分镜规划。
- 剧本室和项目列表均可新增一集：选择集名及创作起点，创建后聚焦新集。继承作品共享模型、Bible，以及已有分集的制作规格。
- 「AI 辅助创作」接受创作想法或修订要求；「根据改编规划生成」仍要求有效的分集规划。两者共用持久化任务系统及项目默认文本模型。
- 直接创作时，原著资料和改编策划收在顶部「原著改编」可选入口中，正文和目标时长常显，补充信息折叠。
- 剧本页保存会同步画布正式剧本投影。独立画布草稿通过「采用为本集剧本」进入同一份正文；替换已有正文前确认，历史版本仍保存在数据库。

## 数据和兼容

- `Project.document.creationMode` 为当前集的入口偏好：`direct` / `adaptation`，不阻止后续使用另一条创作路径。
- 浏览器新建显式发送 `creation_mode=direct`。旧 API 调用未指定时保留 `adaptation`，避免改变历史调用语义；已有项目不批量迁移。
- 剧本列表为实际分集与分集规划的并集；已存在的分集可以在没有对应规划时读写剧本。
- 正文仍以 `episode_scripts` 为唯一来源；画布使用既有投影机制，不建立第二份剧本数据。
- 手写直接剧本标记 `metadata.adaptationLinked=false`。无来源引用时，改编规划更新不会使其过期；明确引用的原著章节改变仍会使其过期。
- 新增 `POST /api/productions/{id}/episode-scripts/{no}/assist`，使用 `direct-episode-script/v1` 契约。任务冻结正文版本、创作要求、项目规格、Bible、视觉资产摘要及最多三集前集承接（每集正文末 8000 字符）。
- 同集活动任务去重。执行期间正文版本或上下文变化，旧结果拒绝回写；已有成片视频的集不会被 AI 自动重写，仍可手工修订。
- AI 输出只写入目标集。历史改编任务保持原模式及完成逻辑。

## 验证

- 后端覆盖无规划的 EP01 / EP02 读写、规格继承、前集上下文、任务幂等与去重、正文并发修改保护、画布采用历史、明确来源变更的过期判断及空要求拒绝。
- 前端覆盖新建默认起点及工作流引导，保留原著改编流程回归。
- 隔离数据库浏览器走查：直接新建 → 写 EP01 → 新增 EP02 → 保存正文 → 进入分镜规划 → 画布正文同步；未调用付费模型。
