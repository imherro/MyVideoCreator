# 分镜图生成参数

分镜图列表 / 宫格与高级画布共用 `ImageGenerationSettings`，写入同一个
image node 的 `provider`、`model` 和 `imageSettings`。供应商和模型范围来自项目模型池。
“恢复项目默认”显式恢复项目模型与推荐尺寸，不在切换供应商时静默丢弃参数。

`POST /api/projects/{pid}/image-spec` 是只读本地预览，不读取上游模型目录，不排任务。
与 `create_job_record` 共用 `resolve_image_settings`。实际提交前必须先保存项目。
预览可传当前未保存的画幅及视频分辨率，以便编辑时立即反馈。

## 尺寸与种子

- 默认推荐尺寸按项目 `ratio` 计算，保持原有约 2K 长边策略。视频分辨率仅作为对照。
- 云端适配器本轮仅开放现有推荐尺寸，不宣称支持任意 480p / 720p 或 4K 出图。
- Maestro 支持自定义像素与视频像素尺寸；ComfyUI 仅在工作流存在宽高占位符时开放。
- 自定义尺寸须与项目画幅相符，并满足像素对齐约束。模型运行时还可能有自身限制。
- 固定种子只在 Maestro 或含 `{{seed}}` 的 ComfyUI 模板中开放。
  云端固定种子未实现，因此明确拒绝新的固定种子设置，不能填了却忽略。
- 本地随机种子在创建任务时冻结实际整数，网络重试复用该整数。
- RunningHub 的尺寸参数与 `2k` 档位共同提交，最终输出像素由服务返回，不能承诺与请求宽高完全相同。

新任务的 `image_spec` 保存解析结果，同时设置 `size`（云端）与 `resolution`（本地）。
任务详情显示提交尺寸和实际种子。批量生成不再覆盖节点尺寸。
设置变更沿用 `patchNode` 的 revision / 下游失效机制；执行中修改参数时，旧结果不会被错误认定为最新。

## 兼容

旧 `node.resolution` 曾被服务端覆盖，不能突然将它视为用户明确选择的新尺寸。
只有 `imageSettings.sizeMode` 声明覆盖意图；旧节点维持原推荐画幅。
不迁移、重写历史任务或历史图片，也不改变远端任务恢复查询路径。

验证覆盖：只读预览不创建任务、单次与批量一致、不同画幅、合法及非法自定义尺寸、
种子能力检查、随机种子重试稳定、旧节点兼容、图像参数编辑与任务结果过期、RunningHub 请求体。
