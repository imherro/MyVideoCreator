# 镜头动作参考与显式视频模式

## 使用

新建项目的默认视频模式为“多模态参考”。项目名称 → 项目设置可以修改默认模式；视频工作区每张镜头卡片，以及高级画布中对应的视频设置，可以覆盖本镜头模式。

1. 在镜头的“动作参考视频”中上传 MP4 并绑定，或选择已有视频素材。每镜头最多一段完整视频，跨镜头可复用。解绑不删除素材，也不会把动作参考加入剪辑轨道。
2. 可选择本镜头已绑定的角色或其基础角色，并选择参考视频运镜、或只参考动作而使用本镜头运镜。补充说明用于处理多主体对应关系。
3. 点击“预览最终提交与参考清单（不生成）”，检查选定/提交模式、图片/视频/音频编号、最终提示词及三个时长。此步骤不调用生成接口。
4. 使用原来的单镜头或批量生成按钮。结果沿用现有任务、素材和剪辑链路。

动作参考是动作顺序、姿态、走位及节奏的参考，不保证逐帧锁定，不提供虚构的动作强度控制。不解析 Blender、骨骼或动画工程。

## 模式与兼容

`Project.document.videoReferenceMode` 保存默认值，`shot.videoReferenceMode` 可覆盖。值为 `multimodal`、`first_frame`、`first_last_frame`，以及用于旧项目的 `legacy`。

- 新项目默认多模态。旧项目无字段时迁移为兼容历史，不更改旧镜头或任务的协议；在旧兼容项目中新建镜头时明确写入多模态。
- 多模态即使只有一张图、无动作、无对白也发送参考协议。角色、场景、道具主参考图和关联图片按顺序去重，动作视频与固定对白追加，不按图片数量换模式。
- 多模态的分镜图是起始构图参考。显式从首尾帧切换到多模态后，原尾帧保留为结束构图参考，实际请求不包含 `first_frame`/`last_frame` 角色。
- 严格首帧/首尾帧是高级选项。含动作、对白或额外视觉绑定等不兼容组合会阻止提交，必须由用户明确修改模式或绑定，不能自动删除素材。
- 改变供应商不会清除绑定。不能实现选定模式的供应商报错，不自动换模型或降级。

依据：[火山方舟创建视频任务文档](https://docs.volcengine.com/docs/82379/1520757)、[RunningHub Seedance 2.5 多模态文档](https://www.runninghub.cn/runninghub-api-doc-en/api-498749513)。接口能力与本项目实现范围不是同一件事；没有核实的模型不放行。

首版动作素材仅 MP4（H.264/H.265）、最大 200 MB。按模型验证时长（2.0 为 2–15 秒、2.5 为 2–30 秒）、24–60 FPS、边长 300–6000、宽高比 0.4–2.5、总像素 407696–8295044，并实际解码校验。同一文件按 SHA256 缓存解码检查。

火山方舟需要可下载动作视频的公网地址，在供应商设置填写；服务器生成短期签名素材链接，浏览器登录地址不会直接发送。RunningHub 使用现有二进制上传链路，适用于工作室仅在局域网内运行的情况。图片和对白沿用既有处理，RunningHub 多模态对白也使用上传后的 URI。

## 时长、声音与持久化

镜头计划时长、动作视频时长、实际提交时长分别保留和展示。提交时长结合项目、对白和模型最短/最长限制；本功能不改写镜头计划、对白，不自动裁剪或变速动作视频。参考时长不同会提示节奏可能重分配，需要时由用户在外部裁剪。

有音轨的动作视频在首次提交前生成可追踪、可复用的无声副本：FFmpeg 仅复制视频流并移除音轨，原始文件保留。无音轨则直接使用原素材。不会为了静音动作参考而关闭任务的对白生成。

编辑状态仅保存 `shot.motionReference`。`backend/motion_references.py` 在预览、单镜头、批量提交中统一编译，任务输入冻结 `generation_mode`、`motion_reference`、`reference_manifest`、`motion_compiler`、提示词和时长。任务详情显示模式及实际媒体清单；派生关系保留原素材 ID 和文件哈希，临时链接不进入任务输入和生成指纹。

修改动作绑定或模式会递增视频及依赖它的下游节点的 `generation_revision`，保留旧结果并标记待更新，不影响无关图片和镜头。旧任务晚到不能清除新配置的过期状态。已有远端编号的任务沿原适配器恢复查询，不重新上传或提交生成。

## 验收

自动测试涵盖新/旧默认模式、单图无动作无对白、多图+动作+对白、编号与幂等编译、预览/单次/批次一致性、严格模式与参考模式转换、非法绑定/文件/媒体限制、真实 FFmpeg 静音副本、原文件保留、局部过期和远端恢复。测试使用隔离数据库、小型本地合成样本及 Mock HTTP，不使用用户项目或付费任务。

真实账号尚需手动验收：分别选择已开通的方舟或 RunningHub 模型，先预览一张图且无动作/对白的请求，再添加一段合法 MP4（有原声也可），确认清单和时长后生成，检查动作、视觉身份、运镜与固定对白。额外测试刷新保留绑定、移除动作不改模式、严格模式必须手工确认切换。真实模型的动作与音色一致性仍应检查实际成片。

## 幻场 AI V3 多模态适配（2026-09-16）

已核对供应商 https://admin-aigc.huanchangai.com/async/doc 的 Seedance 系列及 V3 创建任务说明。`hc_atom` 的 `doubao-seedance-2.0/2.5`（及同系列 dreamina ID）使用 `/v3/video/tasks`：图片登记素材库后以 `reference_image` 提交，动作视频使用静音副本 `reference_video`，角色声音/固定对白以 `reference_audio` 提交。2.5 显式指定 `omni_reference_task_type=reference`。单图亦不降级首帧；项目比例保留。已有远端任务仅恢复查询，不重新提交。

2.0 上限为 9 图、3 音频、15 秒；2.5 为 30 图、10 音频、30 秒。本项目动作参考仍限定每镜一个视频。其他幻场视频模型不因此开放多模态。沿用既有分辨率和严格首帧限制，严格首尾帧未在本次启用。

已完成 Mock HTTP、任务/API 与编译回归；本次未进行真实收费生成，账号厂商授权仍由供应商判定。
